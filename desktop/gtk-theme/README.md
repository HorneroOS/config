# Hornero Signal GTK themes (GTK 3 + GTK 4, MIT-native)

GTK 3 and GTK 4 themes in the Hornero Signal language (RFC 0001): matte
surfaces, 3–5 px radii, 1 px `ruleStrong` control borders, amber `signal`
primary buttons, a celeste `cue` focus ring and selection, on-air bars for
active tabs and rows, and segmented progress. No GTK 2 is shipped or
claimed (the separate `desktop/gtk/gtkrc-2.0` settings skeleton is out of
scope).

## Layout

```text
desktop/gtk-theme/
  src/signal.css              # the one widget stylesheet (source of truth)
  gallery.py                  # widget-gallery fixture (GTK 4, GTK 3 fallback)
  Hornero-Signal/             # Signal Night  (factory default)
  Hornero-Signal-Day/         # Signal Day
  Hornero-Signal-Contrast/    # Signal High Contrast
  Hornero-<Original>/         # one tree per Hornero Original theme
    index.theme, gtk-3.0/gtk.css, gtk-4.0/gtk.css, gtk-4.0/recolor.css
```

Every tree is GENERATED by `scripts/generate-appearance.py`: it prepends the
owning theme's `@define-color` block (each schema-v2 role as `@hs_<role>`
plus the GTK named colours) to `src/signal.css`. A theme in a Hornero
collection (`hornero-signal`, `hornero-originals`) owns the tree named by
its `gtkTheme`; community ports reuse `Hornero-Signal` (dark) or
`Hornero-Signal-Day` (light). Edit `src/signal.css` or a theme's roles,
then regenerate; `scripts/validate.sh` and `tests/test_gtk_theme.sh` fail CI
on drift, undefined colours, radii outside the Signal scale, or (where
PyGObject is installed) any error from the real GTK 3 and GTK 4 parsers
(`tests/gtk_css_parse.py`, display-free).

## Source architecture

Original hand-structured CSS, no SCSS toolchain and no vendored upstream
trees (copyleft SCSS themes cannot enter this MIT repo). Only the portable
subset valid in both parsers is used: no colour functions, no engines, no
imports, no GTK 4-only pseudo-classes. GTK 3 and GTK 4 outputs are
byte-identical.

## Libadwaita: public-palette redefinition, no restyle

Libadwaita apps ignore GTK theme trees. Each tree ships `gtk-4.0/recolor.css`
redefining only Libadwaita's documented named colours (`accent_bg_color` =
`signal`, `window_bg_color` = `base`, `error_bg_color` = `alert`, …).
`materialize.sh` installs the Signal Night copy as
`~/.config/gtk-4.0/gtk.css`; applying a theme copies the recolour of the
theme's `gtkTheme` tree (`_hornero_appearance_sync_recolor`).

## Install paths and package ownership

| Repo source | User install (`materialize.sh --dest`) | Package (`PKGBUILD`) |
| --- | --- | --- |
| `desktop/gtk-theme/Hornero-*` | `~/.local/share/themes/Hornero-*` | `/usr/share/themes/Hornero-*` |
| `desktop/gtk-theme/{src,gallery.py,README.md}` | not installed (dev-only) | not installed |

The recipe JSONs stay under `/usr/share/hornero/themes`; the GTK trees live
only under `/usr/share/themes`. No file is owned twice.

## Applying

```sh
hornero-appearance theme apply hornero-signal-day   # full theme apply
hornero-gtk-theme apply Hornero-Signal Papirus-Dark prefer-dark
python3 desktop/gtk-theme/gallery.py --theme Hornero-Signal
```
